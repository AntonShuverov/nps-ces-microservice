# Микросервис NPS CES

Сервис, который показывает клиентам на сайте короткий опрос и собирает их оценки: **CES** (насколько легко было пройти шаг) и **NPS** (готовы ли порекомендовать нас).

## Что делает сервис

1. Клиент проходит важный шаг на сайте, например погашает займ.
2. Через пару секунд на экране появляется опрос по макетам из Figma: шаг 1 — NPS («Насколько вероятно, что вы порекомендуете наш сервис?», 1–10), шаг 2 — CES («Насколько легко оплатить займ в Личном кабинете?», пять смайликов). При низкой оценке появляется поле для комментария. На старте опрос только на погашении займа; короткие опросы CES после выдачи займа и после заявки заведены, но выключены.
3. Ответы сохраняются в базу сервиса, оттуда загружаются в DWH, а метрики NPS и CES считаются в BI.

Правила показа:
- опрос показывается каждый раз, когда клиент снова доходит до события, но **не чаще одного раза в день**;
- кому показывать, настраивается гибко: новым или повторным клиентам, по продукту, каналу, номеру займа, только части клиентов (например, 30%);
- если клиент ответил на NPS и закрыл опрос на CES, NPS считается отвеченным, а CES — закрытым (и наоборот при другом порядке шагов);
- если сервис опросов недоступен, клиент этого не заметит: опрос просто не появится, оформление займа не пострадает.

## Из чего состоит

| Часть | Что делает | На чем написана |
|---|---|---|
| **Сервис опросов** (`backend/`) | Решает, показывать ли опрос, отдает вопросы, проверяет и сохраняет ответы | Java 21, Spring Boot 3.5 |
| **База данных** | Хранит опросы, вопросы, условия показа, факты показа и ответы | PostgreSQL 16, миграции Flyway |
| **Виджет для сайта** (`widget/`) | Рисует поп-ап с опросом, отправляет ответы в сервис. Работает на десктопе и в мобильной версии (нижняя шторка) | TypeScript, без сторонних библиотек |
| **Витрина для аналитики** (`dwh/`) | Пример SQL: одна строка на каждый вопрос каждого показа, удобно считать NPS и CES в BI | SQL |
| **Тесты и CI** | 43 теста сервиса и 10 тестов виджета, запускаются на GitHub при каждом изменении | JUnit 5, Testcontainers, Vitest, GitHub Actions |
| **Документация API** | Страница со всеми запросами, их можно отправить прямо из браузера | OpenAPI, Swagger UI |
| **Запуск** | Сборка образа и локальный запуск вместе с базой | Docker, Docker Compose |

## Как части связаны

```
Сайт + виджет  ──►  API gateway  ──►  Сервис опросов  ──►  PostgreSQL  ──►  DWH  ──►  BI
                    (авторизация)          │
                                           └──► сервис клиентов (атрибуты для условий показа)
```

Сервис опросов — отдельное приложение со своими таблицами. В код и базу других сервисов он не лезет.

## Прототип

**[nps-ces-prototype.html](nps-ces-prototype.html)** — интерактивный прототип опроса. Скачайте файл (кнопка Download raw file на странице файла) и откройте двойным кликом в браузере. Сервер и интернет не нужны, кроме загрузки шрифта цифр.

В прототипе можно выбрать событие (займ погашен, займ выдан, заявка отправлена), пройти опрос на десктопе и в мобильном виде и посмотреть, какие запросы виджет отправил бы в сервис. Внутри настоящий виджет из репозитория, сервер заменен заглушкой с теми же опросами.

После изменений виджета прототип пересобирается командой `cd widget && npm run prototype`. CI проверяет, что файл в репозитории не устарел.

`widget/demo/index.html` — другая страница: она для разработчиков и работает только вместе с запущенным у себя сервисом (`http://localhost:5173/demo/index.html`).

## Технические детали

Ниже — для разработчиков: запуск, API, настройки.

### Как работает API

```
Виджет                               Сервис опросов
  │  GET  /active?flowStep=…           │ проверить правила, вернуть опрос или «опроса нет»
  │  POST /impressions                 │ зафиксировать показ после отрисовки поп-апа
  │  PUT  /impressions/{id}/steps/N    │ проверить и сохранить ответы шага
  │  POST /impressions/{id}/close      │ запомнить шаг, на котором клиент закрыл опрос
```

### Быстрый старт

Нужны Docker, Node.js 20+.

```bash
# PostgreSQL + сервис с примерами опросов (профиль dev)
docker compose up --build

# Демо-страница виджета: http://localhost:5173/demo/index.html
cd widget && npm install && npm run dev
```

Примеры опросов заводятся только в пустую базу. Если они поменялись в репозитории, пересоздайте локальную базу: `docker compose down -v`.

Без Docker: запустите PostgreSQL, создайте БД `survey` (пользователь и пароль `survey`) и выполните `cd backend && SPRING_PROFILES_ACTIVE=dev mvn spring-boot:run`.

### Бэкенд

#### API

Все запросы идут через API gateway. Gateway авторизует клиента и передает его ID в заголовке `X-Client-Id`. Фронт ID клиента не передает.

> Gateway обязан удалять `X-Client-Id` из входящих внешних запросов, иначе клиент сможет отвечать от имени другого.

| Операция | Запрос | Ответ |
|---|---|---|
| Получить опрос для шага | `GET /api/v1/surveys/active?flowStep=loan_issued` | `200` конфигурация опроса или `204` |
| Зафиксировать показ | `POST /api/v1/surveys/impressions` `{"surveyId": 2, "flowStep": "loan_issued", "eventObjectId": "loan-42"}` | `201 {"impressionId": "…"}` или `409`, если показать уже нельзя |
| Сохранить ответы шага | `PUT /api/v1/surveys/impressions/{id}/steps/1` `{"answers": [{"questionId": 2, "value": 6}]}` | `200 {"status": "SHOWN", "lastStep": 1, "completed": false}`, `422` при ошибках валидации |
| Закрыть опрос | `POST /api/v1/surveys/impressions/{id}/close` `{"step": 2}` | `204` |

Значение ответа: число для шкалы и звезд, строка для текста и выбора одного, массив строк для выбора нескольких.

#### Настройки

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `DB_URL`, `DB_USER`, `DB_PASSWORD` | `jdbc:postgresql://localhost:5432/survey`, `survey`, `survey` | Подключение к БД |
| `SURVEY_ENABLED` | `true` | Аварийный флаг: `false` — опросы не показываются |
| `SURVEY_BUSINESS_ZONE` | `Europe/Moscow` | Часовой пояс для правила «1 раз в день» |
| `SURVEY_GLOBAL_DAILY_LIMIT` | `0` | Максимум показов любых опросов клиенту за день, `0` — без лимита |
| `SURVEY_CLIENT_ID_HEADER` | `X-Client-Id` | Заголовок с ID клиента от gateway |
| `SURVEY_RATE_LIMIT_PER_MINUTE` | `60` | Лимит запросов одного клиента в минуту |
| `SURVEY_CLIENT_ATTRIBUTES_URL` | пусто | Сервис клиентов для атрибутов условий: `GET {url}/clients/{id}/attributes` |
| `SURVEY_CORS_ALLOWED_ORIGINS` | пусто | Домены сайта, если виджет ходит в сервис напрямую, а не через gateway |

Документация API: `/swagger-ui.html` (отключается `SURVEY_API_DOCS_ENABLED=false`).
Метрики Prometheus: `/actuator/prometheus`, health-проверки: `/actuator/health/liveness`, `/actuator/health/readiness`.

Конфигурация активных опросов проверяется при старте и раз в 5 минут (`SURVEY_CONFIG_CHECK_INTERVAL`): шаги, шкалы, варианты ответов, условия триггеров. Опрос с ошибками не показывается клиентам, ошибки пишутся в лог, число таких опросов — в метрике `survey_config_invalid`.

#### Как завести опрос

Опросы заводятся миграцией Flyway в `backend/src/main/resources/db/migration` (пример заполнения — `db/seed/R__example_surveys.sql`, он подключается только в профиле `dev`).

Условия триггера — JSON-массив, условия объединяются через «И»:

```json
[
  {"attribute": "client_type", "op": "eq", "value": "repeat"},
  {"attribute": "product", "op": "in", "value": ["PDL", "IL"]},
  {"attribute": "loan_number", "op": "gte", "value": 2}
]
```

Операторы: `eq`, `neq`, `in`, `not_in`, `gt`, `gte`, `lt`, `lte`. Доля показа задается в `survey_trigger.show_percent`.

Вид вопроса и условный показ задаются в `settings` вопроса:

```json
{"min": 1, "max": 5, "view": "emoji"}
{"placeholder": "Ваш комментарий здесь", "showIf": {"question": "ces", "op": "lte", "value": 3}}
```

`view: "emoji"` — шкала смайликами (CES), без него — радиокнопки с цифрами (NPS). `showIf` — вопрос виден, только если ответ на другой вопрос подходит: так комментарий появляется только при низкой оценке.

У вопроса, на который уже есть ответы, нельзя менять текст, тип, шкалу и варианты: это запрещено триггером в БД. Для изменений создается новый опрос с новым кодом.

### Виджет

```bash
cd widget
npm install
npm test        # тесты
npm run build   # dist/survey-widget.js (ES-модуль) и dist/survey-widget.iife.js (для тега <script>)
```

Подключение на сайте:

```js
import { initSurveys, showSurvey } from 'survey-widget';

initSurveys({ baseUrl: '/api/v1/surveys' });

// на шаге «Займ выдан», после загрузки основного контента
showSurvey('loan_issued', { eventObjectId: loan.id });
```

Через тег `<script>`: `SurveyWidget.initSurveys({...})` и `SurveyWidget.showSurvey('loan_issued')`.

| Опция | По умолчанию | Назначение |
|---|---|---|
| `baseUrl` | `/api/v1/surveys` | Адрес API |
| `delayMs` | `2000` | Задержка перед показом, чтобы клиент сначала увидел результат шага |
| `requestTimeoutMs` | `1500` | Таймаут запроса опроса, при таймауте опрос не показывается |
| `headers` | — | Дополнительные заголовки, если авторизация не на cookie |
| `isOtherModalOpen` | ищет `[aria-modal="true"]` и `dialog[open]` | Не показывать опрос поверх другого модального окна |
| `closeOnEsc`, `closeOnOutsideClick` | `true` | Закрытие по Esc и клику вне поп-апа, засчитывается как крестик |
| `thankYouAutoCloseMs` | `4000` | Автозакрытие экрана благодарности, `0` — не закрывать |
| `texts` | русские тексты | Тексты кнопок и сообщений |

Виджет запрашивает опрос один раз за визит на шаг: повторные вызовы при перерисовке игнорируются. В SPA при новом визите вызовите `resetSurveyVisit('loan_issued')`.
