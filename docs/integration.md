# Интеграция: инструкция для техлида и архитектора

Что лежит в репозитории, как это встроить в текущую инфраструктуру и какие решения нужно принять. Требования к функциональности — в [survey-service.md](survey-service.md).

## Что готово

| Компонент | Папка | Состояние |
|---|---|---|
| Сервис опросов (Java 21, Spring Boot 3.5) | `backend/` | Готов, 34 теста |
| Схема БД (PostgreSQL, миграции Flyway) | `backend/src/main/resources/db/migration/` | Готова |
| Виджет поп-апа для сайта (TypeScript, без зависимостей) | `widget/` | Готов, 10 тестов |
| Пример витрины для DWH/BI | `dwh/` | Пример, адаптировать под DWH |
| Локальный запуск | `docker-compose.yml` | PostgreSQL + сервис с примерами опросов |

## Архитектура

```
Браузер (сайт + виджет)
      │  /api/v1/surveys/*   (cookie/токен сайта)
      ▼
API gateway ── авторизация, выставляет X-Client-Id, удаляет его из внешних запросов
      │
      ▼
survey-service ──► PostgreSQL (своя схема/БД, 5 таблиц)  ──► загрузка в DWH ──► BI
      │
      └──► сервис клиентов: GET /clients/{id}/attributes  (для условий показа, опционально)
```

Сервис не обращается к БД и коду других сервисов. Точки интеграции — только перечисленные выше.

## Варианты встраивания

| | Отдельный сервис (рекомендуется) | Модуль в текущем бэке |
|---|---|---|
| Что сделать | Задеплоить `backend/` как новый сервис по стандартному шаблону | Перенести пакет `ru.survey.service` и миграции в существующее Spring-приложение |
| БД | Отдельная схема в существующем PostgreSQL или отдельная БД | Отдельная схема в БД бэка |
| Плюсы | Изоляция: сбой опросов не задевает выдачу займов, независимые релизы | Не нужен новый деплой |
| Минусы | Еще один сервис в мониторинге и CI/CD | Общий релиз и общий риск с основным сервисом |

## Чек-лист интеграции

**Инфраструктура**
- [ ] Выбрать вариант встраивания (таблица выше).
- [ ] Создать БД или схему в PostgreSQL и пользователя для сервиса. Миграции Flyway применятся при старте.
- [ ] Собрать образ (`backend/Dockerfile`) или подключить сборку к своему CI/CD.
- [ ] Health-проверки: `/actuator/health/liveness`, `/actuator/health/readiness`. Метрики: `/actuator/prometheus`.
- [ ] Алерты на рост ошибок и время ответа выше 1,5 с (таймаут виджета).

**API gateway**
- [ ] Маршрут `/api/v1/surveys/**` → survey-service.
- [ ] Gateway после авторизации выставляет заголовок с ID клиента (по умолчанию `X-Client-Id`, меняется через `SURVEY_CLIENT_ID_HEADER`).
- [ ] **Обязательно:** gateway удаляет этот заголовок из входящих внешних запросов. Иначе клиент сможет отвечать от имени другого.
- [ ] Если у вас другая схема авторизации (JWT в сервисе, внутренний auth-сервис), заменить `web/ClientIdentityFilter.java`. Остальной код от этого не зависит.

**Атрибуты клиента для условий показа** (можно отложить)
- [ ] Сервис клиентов отдает `GET /clients/{id}/attributes` с плоским JSON: `{"client_type": "repeat", "product": "PDL", "loan_number": 3}`, и его адрес задается в `SURVEY_CLIENT_ATTRIBUTES_URL`.
- [ ] Или реализовать свой `client/ClientAttributesProvider` (например, читать из своей БД или кэша).
- [ ] Пока не настроено, опросы без условий работают, опросы с условиями не показываются.

**Сайт**
- [ ] Собрать виджет (`cd widget && npm run build`) и подключить: ES-модуль `dist/survey-widget.js` или `<script>` с `dist/survey-widget.iife.js`. Либо скопировать `widget/src` в репозиторий сайта.
- [ ] На шагах флоу вызвать `showSurvey('<код шага>', { eventObjectId: <ID займа> })` после загрузки основного контента.
- [ ] Если на сайте есть свой менеджер модальных окон, передать `isOtherModalOpen` в `initSurveys`.
- [ ] Проверить стили поп-апа против макетов из Figma (`widget/src/styles.ts`).

**DWH**
- [ ] Подключить таблицы `survey`, `survey_question`, `survey_trigger`, `survey_impression`, `survey_answer` к текущему механизму загрузки. Для инкрементальной загрузки есть индексы по `updated_at`.
- [ ] Сверить формат `client_id` и `event_object_id` с форматом ID клиента и займа в DWH.
- [ ] Построить витрину по примеру `dwh/survey_question_result.sql`.

**Опросы**
- [ ] Продукт готовит конфигурацию опросов (вопросы, тексты, шкалы, шаги флоу, условия, доля показа).
- [ ] Разработчик заводит ее миграцией в `db/migration` по образцу `db/seed/R__example_surveys.sql`. Примеры из `db/seed` в прод не попадают.

| Логика виджета | `widget/src/index.ts`, `widget/src/popup.ts` |

## Известные ограничения

- Лимит запросов на клиента считается в памяти одного экземпляра. При нескольких экземплярах основной лимит лучше держать на gateway.
- `docker compose` и тесты через Testcontainers не прогонялись в среде разработки (не было Docker). Тесты проверены на локальном PostgreSQL 16: `TEST_DB_URL=... mvn test`.
- Принадлежность `eventObjectId` (займа) клиенту сервис не проверяет, он хранится как справочное значение.
